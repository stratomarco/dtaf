# Contribution review checklist

- Pin the actual system version and define the examined path and exclusions.
- Confirm scope, existing work, ownership and terminology with maintainers.
- Separate observed behavior, assumptions, candidate requirements and verified failures.
- Trace each threat to an expectation, control, evidence and remaining risk.
- Distinguish standalone implementation from integration and deployment.
- Record functional and adversarial tests independently, with actual execution results.
- Justify not-applicable decisions; keep unavailable access as a limitation.
- Record residual risk even when assessment is completed or controls are effective.
- Separate implementation ownership from risk acceptance authority; preserve pending decisions.
- Check audit completeness, provenance, integrity, retention and access control.
- Use project-native language and keep contributions focused on its architecture.
- Check local links, placeholders, sensitive data and claims before submission.

These materials are templates and a fictional example. They do not establish the security of any project. Review external technique IDs and references against their authoritative sources before relying on them.
